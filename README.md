# 🕸️ Web Auto Move

**スクリーンショットに赤枠を引いて、ノードを矢印でつなぐだけで、Webスクレイピングのプログラム（Python）を自動生成するツールです。**

プログラミングの知識がなくても、「このボタンを押す → この情報を取る → このフォルダに保存する」という流れを画面上で組み立てるだけで、それを何百回・何千回でも自動実行できる Python スクリプトが手に入ります。

すべてブラウザの中だけで動きます。**サーバーには何も送信されません。**

---

## できること

| やりたいこと | 対応するノード |
|---|---|
| ボタンやリンクを押す | 👆 クリック |
| 検索欄に文字を入れる | ⌨️ 文字入力（IDやパスワードは環境変数から安全に読み込み） |
| ページ内の文字・URLを取り出す | 🔍 情報取得（正規表現での切り出しも可） |
| 商品一覧・検索結果をまとめて表にする | 📋 一覧取得 |
| ファイルをダウンロードする | ⬇️ ダウンロード |
| フォルダを作って振り分ける | 📁 フォルダ作成（`{{today}}/{{商品名}}` のような自動命名） |
| メモ・Word・Excel/CSV で保存する | 📝 メモ保存 / 📄 Word保存 / 📊 Excel・CSV保存 |
| 同じ処理を何百回も繰り返す | 🔁 繰り返し（回数指定／一覧の各項目／CSVの各行／ページ送り） |
| 出たり出なかったりする画面に対応する | 🔀 条件分岐 |
| 「次へ」が無くなるまでページを進む | 🔁 繰り返し（ページ送りモード） |
| ページ全体・要素の画像を残す | 📸 スクショ保存 |
| 実行前に流れを紙芝居で確認する | ▶ プレビュー（キャンバス上部） |
| 実行中・実行後に「実際に開いた画面」を見る | 🖼 実行レポート（`output/run_report.html` に自動記録） |
| その他こまごました操作 | 🧭 ページ移動 / 🔤 キー入力 / 🔽 プルダウン選択 / 🖐️ マウスを乗せる / 📎 ファイル添付 / 📜 スクロール / ⏳ 待機 / 🖼️ フレーム切替 / 🐍 カスタムコード / 💬 ログ出力 / 🛑 停止 |

生成されるのは **Playwright (Python)** のスクリプトです。依存は `playwright` と、必要に応じて `python-docx` / `openpyxl` だけ。

## 使い方

### 1. フローを組み立てる

1. **開始**ノードに、最初に開くURLを入れます。
2. 左のパレットから、やりたい操作のノードを足していきます（クリックすると自動で前のノードとつながります）。
3. ノードの右の ● から次のノードへドラッグすると、矢印でつながります。

### 2. 「どのボタンか」をプログラムに教える

プログラムは画像を見て「このボタン」を判断できません。そこで2つの方法を組み合わせます。

**A. スクリーンショットに印をつける（人間用のメモ）**

「🖍 スクショに印をつける」から画像をアップロードし、赤枠・蛍光ペン・矢印・ピンで押したい場所を囲みます。
Windows なら <kbd>Win</kbd>+<kbd>Shift</kbd>+<kbd>S</kbd>、Mac なら <kbd>Cmd</kbd>+<kbd>Shift</kbd>+<kbd>4</kbd> で撮った画像を <kbd>Ctrl</kbd>+<kbd>V</kbd> でそのまま貼れます。
この印はフローに保存され、生成コードにもコメントとして残るので、後から見返したときに画面と対応づけられます。

**B. HTMLからセレクタを自動推定（プログラム用の指定）**

1. 対象のサイトで押したいボタンを **右クリック → 検証**
2. 青くハイライトされた行を **右クリック → Copy → Copy outerHTML**
3. 「🔎 HTMLから推定」に貼り付け

貼り付けると、`data-testid` / `id` / `name` / `aria-label` / 役割＋名前 / 表示文字 / class など複数の候補を作り、**安定度（壊れにくさ）で採点して並べます**。
`css-1x2y3z` のような自動生成クラスや、`div > ul > li:nth-child(3)` のような並び順頼みの指定は減点され、翌週には動かなくなるような選択を避けられます。

ページ全体のHTMLを貼って「絞り込みキーワード」（例：`ログイン`）を入れる方法でもかまいません。
一覧取得では、同じ形が繰り返されている部分を自動検出し、列（タイトル・リンク・価格など）まで一括で設定できます。

### 3. 変数でつなぐ

**情報取得**ノードで取り出した値には名前を付けられます。以降のノードで `{{名前}}` と書くと差し込まれます。

```
フォルダのパス:  {{today}}/{{商品名}}
ファイル名:      {{index}}_{{商品名}}.pdf
メモの内容:      価格: {{価格}}\nURL: {{page_url}}
```

組み込み変数：`{{today}}` `{{now}}` `{{timestamp}}` `{{index}}` `{{page_title}}` `{{page_url}}` `{{last_download}}` `{{item.列名}}`

### 4. 実行する（2通り）

**A. 「▶ 実行」ボタン — 画面から直接動かす（おすすめ）**

画面右上の「▶ 実行」から、PCに置く小さな実行環境 `wam_runner.py`（Pythonファイル1個・このリポジトリに同梱）に接続すると、**フロー編集画面からそのまま実行**できます。

1. Python を入れる（初回のみ）
2. 「▶ 実行」画面から `wam_runner.py` をダウンロードしてダブルクリック → 黒い画面に**接続コード**が出る
3. 接続コードを入力して接続 → **「▶ このフローを実行」**

実行するとPC上でブラウザが立ち上がって実際に動き、ログがリアルタイムに流れ、`ホームフォルダ/WebAutoMove/` の下に結果が保存されます。実行レポート（開いた画面の記録）もボタン1つで開けます。実行環境は 127.0.0.1 のみで待ち受け、接続コードを知らないページからは操作できません。

**B. コードを書き出して自分で実行する**

「⚡ コード生成」を押すと、`scraper.py` / `requirements.txt` / `README.md` が作られます。
「📦 一式ダウンロード」でZIP（フロー定義 `flow.json` 込み）としても取り出せます。

```bash
pip install -r requirements.txt
python -m playwright install chromium
python scraper.py
```

最初は開始ノードの「ヘッドレス」を**オフ**にして、ブラウザの動きを目で見ながら確認するのがおすすめです。

### 5. 保存・共有

フローはブラウザ内（IndexedDB）に自動保存されます。
**📤 エクスポート**でJSONファイルとして書き出し、**📥 インポート**で読み込めます。スクリーンショットも含めて1ファイルにまとまるので、別のPCへ持っていったり、チームで共有したりできます。

## 実行の様子を「見る」

- **▶ プレビュー**（キャンバス上部のボタン）… 実行前に、フローが動く順番を紙芝居のように確認できます。各ノードに付けた赤枠つきスクショが順番に並び、クリックするとそのノードの設定に飛べます。
- **実行レポート** … 実行すると `output/run_report.html` に「実際に開いた画面」が1ステップずつ画像つきで記録されます。**実行中にブラウザで開くと5秒ごとに自動更新される**ので、ヘッドレス（画面なし）で動かしていても進み具合が見えます。エラーが起きた場合はその瞬間の画面も記録されます。開始ノードの「実行レポートを作る」でオン／オフ、「記録する画像の上限」で枚数を調整できます。

## 大量処理のコツ

- **繰り返しノードの「最大処理件数」を最初は 3 くらいにして試す。** 意図通り動くのを確認してから 0（全部）にします。
- **「1件失敗しても次の件へ進む」をオンに。** 失敗した件の画面は `output/errors/` に自動保存され、ログにも残ります。
- **「何件目から始めるか」で再開できます。** 500件目で止まったら 500 を入れて再実行すれば続きから処理できます。
- **`POLITE_WAIT`（1件ごとの待ち時間）は 1〜2秒を推奨。** 相手のサーバーに負荷をかけないためのマナーです。
- **CSVを入力にすると強力です。** URL一覧をCSVに並べ、繰り返しノードの「CSVの各行」モードで流し込めば、見出し名がそのまま `{{url}}` のように変数として使えます。

## 開発・公開

ビルド工程はありません。素の HTML / CSS / JavaScript のみで動きます。

```bash
# ローカルで開く（index.html をブラウザで直接開くだけでも動きます）
python3 -m http.server 8000
```

`main` ブランチへの push で、`.github/workflows/deploy.yml` が GitHub Pages へ自動デプロイします。
リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** に設定してください。

### ファイル構成

```
index.html          画面の骨組み
css/style.css       スタイル（ライト／ダーク対応）
js/util.js          共通ユーティリティ、IndexedDB、Pythonシンタックスハイライト
js/nodes.js         ノード種別の定義（このツールの心臓部）
js/selector.js      HTML → 壊れにくいCSSセレクタの推定・採点
js/annotator.js     スクリーンショットへの赤枠・蛍光ペン描画
js/flow.js          ノードと矢印のキャンバス（ドラッグ・接続・ズーム・自動整列）
js/inspector.js     右パネルのノード設定エディタ
js/codegen.js       フロー → Playwright(Python) のコード生成
js/samples.js       サンプルフロー
js/app.js           全体の配線（保存・書き出し・コード表示）
```

## 注意

- 対象サイトの**利用規約**と `robots.txt` を確認してから使ってください。自動アクセスを禁じているサイトがあります。
- IDやパスワードはコードに直接書かず、**環境変数から読み込む**設定（文字入力ノードの「環境変数から読み込む」）を使ってください。
- 短い間隔での大量アクセスは相手のサーバーに負荷をかけます。待ち時間を適切に設定してください。
